# OpAMP Commander for Grafana

Development foundation for the read-only fleet visibility milestone [#803](https://github.com/minuk-dev/opampcommander/issues/803).

This draft loads an app and a nested Go data source in Grafana. It does **not** connect to Commander yet: queries return an explicit not-implemented error and connection checks report an error. No generated sample metrics or healthy empty fleet is returned.

## Local development

Requirements: Node.js 24 LTS, npm 11, Go 1.26.5+, Docker Compose v2.

From the repository root, start the preview with one command:

```sh
make grafana-demo
# Open http://127.0.0.1:3300/a/minukdev-opampcommander-app
# make grafana-demo-logs  # follow logs
# make grafana-demo-stop # remove the demo container and network
```

This installs locked dependencies, builds both plugin parts, and recreates Grafana so backend and manifest changes take effect. The preview shows the app shell and an explicit unavailable-query state; it does not display a live fleet yet. Only Grafana is started. Demo state is disposable. The default Go memory target is 256 MiB for small Docker VMs; override it with `GRAFANA_GOMEMLIMIT` if needed.

For development and checks:

```sh
cd plugins/grafana
npm ci
make check
make serve
```

Open http://127.0.0.1:3300/a/minukdev-opampcommander-app. The loopback-only development instance permits anonymous Viewer access and provisions the app and data source without upstream credentials. `GRAFANA_PORT` changes the host port; `GRAFANA_VERSION` selects the image (default 13.2.3). Do not expose this development instance publicly.

```sh
npx playwright install chromium
npm run e2e
make stop
```

Set `GRAFANA_URL` when running tests against a different host port. Tests exercise the page as a Viewer at desktop and 375px widths. After changing either `plugin.json`, rebuild and restart Grafana (`docker compose restart grafana`). Use `npm run dev` for frontend watch builds; rebuild the Go backend with `make backend` and restart Grafana after backend changes.

## Layout and builds

- `src/module.tsx`: app entry point and preview page.
- `src/datasource/`: nested data source, with its own manifest and entry point.
- `pkg/`: Go data-source process; no dependency on the Commander server module.
- `.config/`: unmodified build configuration generated by `@grafana/create-plugin` 7.13.0.
- `Magefile.go`: Grafana SDK backend build targets. `make backend` produces Linux amd64/arm64 executables in `dist/datasource/`.
- `provisioning/`: local app/data-source provisioning.

The frontend uses Grafana 13.2.3 packages with React 19. Both manifests require Grafana >=13.2.0; CI smoke-tests 13.2.0 and 13.2.3. Versions outside this matrix are not yet validated. `make build` produces the app in `dist/` with the nested data source and its backend binaries. Production signing and ZIP release automation belong to #809.

The root server and `web/` builds remain independent of this package. Run checks from this directory; the separate `go.mod` intentionally excludes plugin packages from the root Go test command. CI lives at the repository root in `.github/workflows/grafana-ci.yaml`.
