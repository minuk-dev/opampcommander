# OpAMP Commander for Grafana

Development foundation for the read-only fleet visibility milestone [#803](https://github.com/minuk-dev/opampcommander/issues/803).

This draft queries the Commander REST API through the Grafana Go backend and displays a namespace's agents, connection state, reported health and last-report timestamp. Credentials stay in Grafana's encrypted data-source settings. This is current-state visibility, not time-series history.

## Local fleet demo

Requirements: Node.js 24 LTS, npm 11, Go 1.26.5+, Python 3, Docker Compose v2.

From the repository root:

```sh
make grafana-demo
# Open http://127.0.0.1:3300/a/minukdev-opampcommander-app
make grafana-demo-logs
make grafana-demo-stop
```

This builds the plugin and current Commander server, then starts an in-memory
Commander and two real OpenTelemetry Collectors, then stops one to demonstrate
both connected and disconnected states. The page labels them as a local
demo. They report through OpAMP to the disposable Commander server. Grafana reads
the private demo REST endpoint. Restarting the demo resets the Commander fleet.
Host ports bind to loopback. Set `GRAFANA_PORT` (default 3300) or
`COMMANDER_DEMO_PORT` (default 3301) to override them.

Run the live browser checks with:

```sh
cd plugins/grafana
npx playwright install chromium
COMMANDER_DEMO=1 npm run e2e
```

Only this demo stack is removed by `make grafana-demo-stop`. The Go memory target
is 128 MiB for Grafana (`GRAFANA_GOMEMLIMIT` overrides it), 128 MiB for Commander,
and 64 MiB per demo Collector. These are GC targets. The demo also caps Grafana at 512 MiB
(`GRAFANA_DEMO_MEMORY_LIMIT` overrides the container limit). Unrelated Grafana data-source
backends are disabled in this disposable demo to keep it usable on small Docker VMs.

## Connect an existing Commander

Add an OpAMP Commander data source in Grafana Connections. Configure its base
URL and namespace, then use **Save & test**. Connect through a private
Commander Service or an access-controlled proxy. Set an access token only
when the configured upstream requires bearer credentials. Grafana stores the
token in its encrypted data-source settings.

Everyone who can query the data source can view Agents in its configured
namespace. Limit data-source access in Grafana and restrict network access to
the Commander backend. Queries retain the administrator-configured host,
namespace and HTTP method. The backend rejects redirects and exports selected
Agent status fields. HTTPS is required except when HTTP is explicitly
enabled in trusted development.

Fleet overview offers a data-source picker, Refresh, Next page and First page.
Each request reads at most 100 agents, with a 10-second timeout and 4 MiB response
cap. Counts describe the displayed page, not the whole fleet. Health is the last
reported value and may be old for a disconnected agent; unsupported/missing
health remains Unknown. Large management-API payloads can exceed the response
cap until #804 provides a compact read projection.

For the unconfigured-plugin smoke test, run `npm ci && make serve` from this
directory, then `npm run e2e`. It must show a configuration error rather than
invented fleet data. `make check` runs frontend/backend checks. After changing a
manifest or Go backend, `make serve` rebuilds and recreates Grafana. Stop a live
demo first with the root `make grafana-demo-stop` before switching environments.

## Layout and builds

- `src/module.tsx`: app entry point and preview page.
- `src/datasource/`: nested data source, with its own manifest and entry point.
- `pkg/`: Go data-source process; no dependency on the Commander server module.
- `.config/`: unmodified build configuration generated by `@grafana/create-plugin` 7.13.0.
- `Magefile.go`: Grafana SDK backend build targets. `make backend` produces Linux amd64/arm64 executables in `dist/datasource/`.
- `provisioning/`: local app/data-source provisioning.

The frontend uses Grafana 13.2.3 packages with React 19. Both manifests require Grafana >=13.2.0; CI smoke-tests 13.2.0 and 13.2.3. Versions outside this matrix are not yet validated. `make build` produces the app in `dist/` with the nested data source and its backend binaries. Production signing and ZIP release automation belong to #809.

The root server and `web/` builds remain independent of this package. Run checks from this directory; the separate `go.mod` intentionally excludes plugin packages from the root Go test command. CI lives at the repository root in `.github/workflows/grafana-ci.yaml`.
